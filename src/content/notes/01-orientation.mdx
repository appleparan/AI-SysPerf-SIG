# 오리엔테이션

첫 모임에서 스터디의 방향과 운영 약속을 정했습니다. 핵심은 발표가 아니라 책과 토론을 중심에 두는 것입니다.

## 발표보다 이해

이 스터디는 발표 중심이 아니라 질문 중심으로 운영합니다. 한 사람이 발표를 준비하고 나머지는 듣는 방식은 사전 학습이 부족하면 수동적인 참여로 끝나기 쉽습니다. 대신 모두가 같은 범위를 읽고, 각자 질문을 준비하고, 함께 설명하며 근거를 확인합니다. 스터디보다는 독서 모임에 가깝습니다.

| 발표 중심 | 질문 중심 |
| --- | --- |
| 한 사람이 발표를 준비한다 | 모두 같은 범위를 읽는다 |
| 다른 사람은 발표를 듣는다 | 각자 질문을 준비한다 |
| 사전 학습이 부족하면 수동적 참여로 끝나기 쉽다 | 함께 설명하고 근거를 확인하며 토론한다 |

학습의 중심은 슬라이드가 아니라 책과 토론입니다.

## 진행 순서

각자 읽고, 질문하고, 서로 답하고, 확인합니다.

1. **Read**: 모두 사전에 교재를 읽는다.
2. **Question**: 이해되지 않는 부분을 질문으로 준비한다.
3. **Discuss**: 함께 설명하고 기술적 근거를 확인한다.
4. **Review**: 이해한 내용과 남은 질문을 정리한다.

질문자는 책을 읽으면서 모르는 내용을 깊이 알아가고, 답변자는 답을 준비하면서 깊이 있는 이해와 다른 시각을 얻어 갑니다.

## 사전 지식과 기대

수준은 Intermediate에서 Advanced 사이의 AI Systems & Infrastructure입니다. 다음 내용은 기본적으로 알고 있다고 가정합니다. 다만 모두 알고 올 필요는 없습니다.

- Transformer와 Attention의 기초
- 딥러닝 학습 및 추론 과정
- CPU / GPU / Memory 기초 개념
- Python 및 Linux 기본 사용

참여자에게 기대하는 태도는 다음과 같습니다.

- 낯선 개념은 사전에 찾아본다.
- 이해한 부분과 막힌 지점을 구분한다.
- 의문을 질문으로 가져온다.
- 서로의 배경과 경험을 존중한다.

## 토론 범위: 기술에 집중

기술적 이해에 기여하는 토론에 집중합니다.

| In scope | Out of scope |
| --- | --- |
| 동작 원리, 아키텍처, 병목 | AI의 사회·경제적 전망 일반론 |
| 측정 및 Benchmark | 근거 없는 미래 예측 |
| 설계 Trade-off, 최적화 | 교재와 무관한 기술 지식 나열 |
| 코드, 논문, 공식 문서 근거 | 현재 질문에서 지나치게 확장된 논의 |

## 운영 약속

모두 똑같이 준비하고 함께 배웁니다.

1. **모두 사전에 읽기**: 매주 정해진 교재 범위를 미리 읽습니다.
2. **질문 미리 제출하기**: 모임 3일 전(목요일)까지 Google Forms로 질문을 제출합니다.
3. **모두 질문하고 답하기**: 발표자와 청중 대신 공동 학습자로 참여합니다.
